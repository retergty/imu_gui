# 飞控 IMU 工作台

在项目目录操作。开发测试环境为 Python 3.12；使用已有的项目虚拟环境，不要复制 Linux 的 `.venv` 到 Windows。新机器请先使用 Python 3.12 创建项目独立环境 `.venv`。

| 操作 | Linux | Windows（PowerShell） |
|---|---|---|
| 安装依赖 | `.venv/bin/python -m pip install -r requirements-gui.txt` | `.\.venv\Scripts\python.exe -m pip install -r requirements-gui.txt` |
| 启动 | `.venv/bin/python app/imu_gui.py` | `.\.venv\Scripts\python.exe app/imu_gui.py` |
| 自测（保留 logs 中的样例与参考报告） | `.venv/bin/python -m unittest discover -s tests -v` | `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` |

- **离线**：打开“本地分析”，选择 VIB2 波形或采样 CSV 即可预览。需要保留报告时点“保存分析结果…”，选择父目录；每次保存都建立独立子目录，不覆盖历史报告。未保存的预览会在分析下一份文件或退出时清除。VIB2 生成 `samples.csv`；采样 CSV 直接用于统计。
- **界面记忆**：分别记住打开波形、保存报告和下载日志的目录。正常退出后，下次恢复上次的主菜单、“下载后分析”选项和 NSH 命令历史；再次分析时会选中上次查看的结果页（如有）。不会自动打开文件或执行历史命令。
- **转速与振动**：主、尾电机各保留一份 CSV。仅当该电机在扫速测点（1～20）有非零平均实测 RPM 时，才生成对应的 PNG 并显示曲线页。横轴是各自的窗口平均实测 RPM；纵轴是同窗机身加速度三轴合成 AC RMS，不是单个电机的独立振动。缺测转速留空且不绘点；实测零转速保留。停转参考点单独标记，不连入扫速曲线。
- **连接**：从列表选择串口和波特率，或手动输入 MAVLink 地址，再点“连接”。点击连接或正常退出时会记住端口（或网络地址）和波特率，下次启动只回填，不自动连接。插入新设备后点“刷新串口”；刷新只列出系统串口，不探测心跳或自动连接。先关闭占用同一串口的地面站；Linux 下请确认当前用户有端口读写权限。连接等待心跳最多 10 秒。
- **IMU 振动测试**：在固定台架上连接飞控后，若产测模块未运行，先点“启动产测模块”。选择电机模式和连续起止测点（1～20，同一点表示单点）；默认不保存。勾选保存后默认使用 `imu_raw.bin`，也可自定义文件名；留空仍使用默认名。飞控上同名文件会被替换。确认开始或正常关闭 GUI 时，会记住电机模式、起止测点、保存选项和文件名。下次打开只回填，不自动开始测试。确认参数后开始，用“查询状态”查看回显，必要时点“中止测试”。断开连接不是停机措施，请保留现场停机手段。保存位置是飞控 SD 卡，不是电脑；日志状态显示 `complete: yes` 后到“飞控日志”页读取目录并下载。
- **日志**：点“读取目录”，选择产测日志并下载。写入临时文件，只有大小与远端目录一致才替换目标。这是长度检查，不是校验和验证。可勾选下载后分析，报告将保存在下载位置旁。
- **NSH**：回车或点发送执行命令；发送空行可唤起提示符。下拉选择历史命令，Ctrl+C 按钮发送中断字符。这是行式控制台，不是完整 ANSI 终端。下载和列目录期间暂停命令，不会重新打开同一串口。通信出错断开后可重连。
- **退出**：等待当前传输或分析结束后关闭。首版不支持中途取消下载。

本地分析中，加速度计和陀螺仪的三轴均值、去均值 RMS 曲线也使用对应电机的平均实测 RPM 作横轴；测点编号仅用于关联数据，不作为横坐标。

## 给最终用户：解压、双击，无需安装 Python

- **Windows x64**：下载 Windows ZIP，右键“全部解压”，进入 `IMUWorkbench` 文件夹，双击 `IMUWorkbench.exe`。可以给它创建桌面快捷方式；不要单独移动 EXE，也不要在压缩包里运行。
- **Linux x86_64**：将 Linux `.tar.gz` 解压到本机用户目录，在图形桌面双击 `IMUWorkbench` 文件夹里的同名程序。若文件管理器没有运行选项，先在文件属性中允许作为程序执行。请先在与构建环境兼容的桌面发行版上试用；Ubuntu 24.04 构建包不保证在更老的系统运行。
- 两个平台都要保留同级 `_internal` 目录。发布包不含飞控 USB 驱动；若串口列表为空，先确认操作系统能识别设备，再刷新串口。

## 给维护者：生成分发包

在项目根目录、目标平台的 Python 3.12 虚拟环境中分别运行。Linux 构建不生成 Windows EXE。

| 平台 | 安装打包依赖 | 构建、启动自检并压缩 |
|---|---|---|
| Windows（PowerShell） | `.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt` | `.\.venv\Scripts\python.exe tools/build_gui.py` |
| Linux | `.venv/bin/python -m pip install -r requirements-build.txt` | `.venv/bin/python tools/build_gui.py` |

将 `dist/` 中对应平台的压缩包发给用户，不需要附上源代码目录、日志数据或 `.venv`。打包脚本会从独立临时工作目录启动成品并检查主窗口能否初始化；此检查不连接飞控。

如项目托管在 GitHub，可在 Actions 手动运行 **Package IMU Workbench**，或推送 `gui-v` 开头的标签。工作流分别在 Windows 和 Ubuntu 上构建；下载 Actions artifact 后，取出里面的平台分发包。正式发布前建议在没有开发环境的目标电脑上解压双击、分析一份本地样例，再连接实际设备验证串口、下载和重连。
